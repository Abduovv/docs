The Arcadia Vault program is a Solana smart contract that enforces all capital flows between investors and traders. Every deposit, withdrawal, and profit settlement happens on-chain — no off-chain custody, no operator override. This page covers the program ID, the Program-Derived Addresses (PDAs) that store state, the instructions you can call, the events the program emits, and the error codes your integration needs to handle gracefully.

<Note>
  The Arcadia program is currently deployed on **devnet**. Mainnet deployment details will be announced. Do not send real funds to the devnet program ID.
</Note>

## Program-Derived Addresses (PDAs)

Arcadia stores all state in PDAs. You derive each account address deterministically from its seeds — no lookups required.

| Account | Seeds | Description |
| --- | --- | --- |
| `PlatformConfig` | `["platform"]` | Global protocol configuration — fees, parameters, admin keys. One account per deployment. |
| `TraderProfile` | `["profile", trader_pubkey]` | One vault per trader. Stores AUM, share count, high-water mark, leverage limits, and vault status. |
| `InvestorAccount` | `["investor", wallet_pubkey]` | One account per investor wallet. Tracks aggregate positions and investor metadata. |
| `InvestorPosition` | `["position", owner_pubkey, profile_pubkey]` | One position per investor × vault pair. Stores share balance and cost basis for a specific vault. |

## Key Instructions

| Instruction | Who calls it | What it does |
| --- | --- | --- |
| `initialize_profile` | Trader | Creates a new `TraderProfile` PDA and initialises the vault with the trader's configuration (leverage limit, capacity, minimum deposit). |
| `deposit` | Investor or trader | Transfers USDC into the vault, mints shares proportional to the current NAV-per-share, and updates the investor's position. |
| `request_withdraw` | Investor | Queues a withdrawal request. Records the number of shares to redeem and sets a `ready_ts` timestamp based on the vault's notice period. |
| `process_withdraw` | Investor | Executes a matured withdrawal request. Burns shares, calculates the USDC redemption amount, and transfers funds to the investor's wallet. Can only be called after `ready_ts` has elapsed. |
| `trader_withdraw_profit` | Trader | Allows the trader to claim accrued performance fees above the high-water mark after a settlement event. |

<Tip>
  Always call `request_withdraw` first and wait for the notice period to elapse before calling `process_withdraw`. Calling `process_withdraw` before `ready_ts` will fail with `NoticeNotElapsed`.
</Tip>

## On-Chain Events

The program emits structured events that your indexer or UI can subscribe to via Solana's program log stream. Each event is anchor-serialised and prefixed with an 8-byte discriminator.

<Accordion title="ProfileInitialized">
  Emitted when a trader creates a new vault by calling `initialize_profile`.

  | Field | Type | Description |
  | --- | --- | --- |
  | `profile` | `Pubkey` | The newly created `TraderProfile` PDA |
  | `trader` | `Pubkey` | The trader's wallet that owns the vault |
  | `score_tier` | `u8` | The trader's score tier at initialisation time |
  | `max_leverage` | `u8` | Maximum leverage allowed in this vault |
</Accordion>

<Accordion title="InvestorInitialized">
  Emitted when an investor's `InvestorAccount` PDA is created for the first time.

  | Field | Type | Description |
  | --- | --- | --- |
  | `account` | `Pubkey` | The newly created `InvestorAccount` PDA |
  | `owner` | `Pubkey` | The investor's wallet |
</Accordion>

<Accordion title="Deposited">
  Emitted when an investor or trader successfully deposits USDC into a vault.

  | Field | Type | Description |
  | --- | --- | --- |
  | `profile` | `Pubkey` | The `TraderProfile` PDA of the vault that received the deposit |
  | `investor` | `Pubkey` | The wallet that made the deposit |
  | `amount` | `u64` | USDC deposited (in lamports, 6 decimals) |
  | `shares` | `u64` | Shares minted in exchange |
  | `nav_per_share` | `u64` | NAV-per-share at the time of deposit |
</Accordion>

<Accordion title="WithdrawRequested">
  Emitted when an investor queues a withdrawal request. The investor must wait until `ready_ts` before processing.

  | Field | Type | Description |
  | --- | --- | --- |
  | `profile` | `Pubkey` | The vault the investor is withdrawing from |
  | `investor` | `Pubkey` | The wallet that submitted the request |
  | `shares` | `u64` | Number of shares queued for redemption |
  | `ready_ts` | `i64` | Unix timestamp after which the withdrawal can be processed |
</Accordion>

<Accordion title="Withdrawn">
  Emitted when a matured withdrawal request is successfully processed and USDC is returned to the investor.

  | Field | Type | Description |
  | --- | --- | --- |
  | `profile` | `Pubkey` | The vault the investor withdrew from |
  | `investor` | `Pubkey` | The wallet that received the USDC |
  | `usdc_out` | `u64` | USDC transferred to the investor (6 decimals) |
  | `shares_burned` | `u64` | Shares redeemed and destroyed |
</Accordion>

<Accordion title="TradeClosed">
  Emitted when a trade is closed and its outcome is recorded on-chain. This is the primary input to the Arcadia Score.

  | Field | Type | Description |
  | --- | --- | --- |
  | `profile` | `Pubkey` | The vault whose trader closed the position |
  | `market` | `Pubkey` | The market or perp account the trade was on |
  | `direction` | `u8` | Trade direction (`0` = long, `1` = short) |
  | `entry_px` | `u64` | Entry price (scaled) |
  | `exit_px` | `u64` | Exit price (scaled) |
  | `realized_pnl` | `i64` | Signed PnL in USDC (positive = profit, negative = loss) |
  | `was_liquidated` | `bool` | Whether the position was closed by liquidation |
</Accordion>

<Accordion title="Settled">
  Emitted at the end of a settlement period. Records the fee split between the trader and the protocol, and updates the vault's high-water mark.

  | Field | Type | Description |
  | --- | --- | --- |
  | `profile` | `Pubkey` | The vault that was settled |
  | `trader_fee` | `u64` | Performance fee credited to the trader |
  | `platform_fee` | `u64` | Management/performance fee credited to Arcadia |
  | `new_hwm` | `u64` | Updated high-water mark NAV-per-share after settlement |
</Accordion>

<Accordion title="ProfitWithdrawn">
  Emitted when a trader successfully withdraws their accrued performance fee.

  | Field | Type | Description |
  | --- | --- | --- |
  | `profile` | `Pubkey` | The vault from which profit was withdrawn |
  | `trader` | `Pubkey` | The trader's wallet that received the USDC |
  | `amount` | `u64` | USDC transferred to the trader (6 decimals) |
</Accordion>

<Accordion title="ExecutionFunded">
  Emitted when an execution account is funded, enabling the trader's agent to submit trades on-chain.

  | Field | Type | Description |
  | --- | --- | --- |
  | `profile` | `Pubkey` | The vault whose execution account was funded |
  | `trader` | `Pubkey` | The trader's wallet |
  | `amount` | `u64` | SOL amount funded (in lamports) |
</Accordion>

## Error Codes

When a transaction fails, the program returns one of the following custom errors. Surface these to users with the descriptions below.

| Error | Meaning | How to handle |
| --- | --- | --- |
| `Unauthorized` | The signer does not have permission to perform this action | Ensure the correct wallet is connected and that it is the vault owner for trader-only instructions. |
| `VaultNotActive` | The vault is paused or closed | Inform the user the vault is not currently accepting activity. Check vault status before submitting. |
| `ZeroAmount` | A deposit or withdrawal of 0 USDC was submitted | Validate that the amount is greater than zero before building the transaction. |
| `InsufficientFunds` | The vault does not have enough USDC to cover the withdrawal | The vault may be fully deployed in open positions. Ask the user to try again after positions settle. |
| `InvalidLeverage` | The leverage value supplied is not valid (e.g. zero or below the minimum) | Validate leverage is within the allowed range before building the transaction. |
| `LeverageTooHigh` | The trade would exceed the vault's configured `max_leverage` | Reduce position size or leverage. Display the vault's current leverage limit to the user. |
| `NotionalTooLarge` | A single trade exceeds 20% of vault AUM | Split the trade into smaller orders or wait for AUM to grow. |
| `CapacityNotSet` | A deposit was attempted before the trader configured a capacity ceiling | The trader must set a `capacityCapUsd` on their vault before investors can deposit. |
| `CapacityExceeded` | The deposit would push vault AUM above its capacity ceiling | Inform the investor the vault is full. They can join a waitlist or try another vault. |
| `DustDeposit` | The deposit amount is below the vault's minimum | Show the minimum deposit amount from the `TraderProfile` account and prompt the user to deposit more. |
| `InsufficientShares` | The investor does not have enough shares to redeem | Validate share balance from the `InvestorPosition` account before building the transaction. |
| `NoticeNotElapsed` | `process_withdraw` was called before `ready_ts` | Display `ready_ts` to the user as a countdown timer. Disable the "Withdraw" button until the timestamp passes. |
| `InsufficientClaimable` | The trader called `trader_withdraw_profit` but has no accrued profit | Disable the claim button until a `Settled` event with a non-zero `trader_fee` has been emitted. |
| `MathOverflow` | An arithmetic operation overflowed | This indicates an unexpected program state. Report the transaction signature to the Arcadia team. |
| `TokenConservationFailed` | Post-instruction token balances do not satisfy conservation checks | This is a safety invariant violation. Report the transaction signature to the Arcadia team. |

<Warning>
  `MathOverflow` and `TokenConservationFailed` are **internal invariant violations**, not user-correctable errors. They indicate a bug or unexpected program state, and cannot be resolved by adjusting inputs or retrying. Surface a generic failure message to the user and report the transaction signature to the Arcadia team rather than prompting the user to retry.
</Warning>

## TypeScript SDK Helpers

<Note>
  **Coming soon.** The `arcadia-sdk` npm package is not yet published. The helpers below reflect the planned public API; expect breaking changes before the first stable release. In the meantime, derive PDAs and fetch account data directly with `@solana/web3.js` and `@coral-xyz/anchor` using the seeds and account layouts documented above.
</Note>

The Arcadia TypeScript SDK (`arcadia-sdk`) will expose utilities for deriving and fetching on-chain accounts. Once published, install it with your package manager, then use the helpers below.

### Derive PDA addresses

```typescript
import { PublicKey } from "@solana/web3.js";
import {
  findTraderProfile,
  findInvestorAccount,
  findInvestorPosition,
} from "arcadia-sdk";

// Derive a trader's vault PDA
const traderKey = new PublicKey("7xKXtg2CW87d97TXJSDpbD5jBkheTqA83TZRuJosgAsU");
const [traderProfile] = findTraderProfile(traderKey);

// Derive an investor's account PDA
const investorKey = new PublicKey("9mZoW3rPqX1sBkL2vCnTy8dFhGjKuRe4iAw6sNpYx5M");
const [investorAccount] = findInvestorAccount(investorKey);

// Derive a specific investor × vault position PDA
const [investorPosition] = findInvestorPosition(investorKey, traderProfile);
```

### Fetch account data

```typescript
import { Connection, PublicKey } from "@solana/web3.js";
import {
  fetchTraderProfile,
  fetchInvestorAccount,
  fetchInvestorPosition,
} from "arcadia-sdk";

const connection = new Connection("https://api.devnet.solana.com");

const traderKey = new PublicKey("7xKXtg2CW87d97TXJSDpbD5jBkheTqA83TZRuJosgAsU");
const investorKey = new PublicKey("9mZoW3rPqX1sBkL2vCnTy8dFhGjKuRe4iAw6sNpYx5M");

// Fetch and decode a TraderProfile account
const profile = await fetchTraderProfile(connection, traderKey);
if (profile) {
  console.log("Total shares:", profile.totalShares);
  console.log("HWM per share:", profile.hwmPerShare);
  console.log("Trader claimable:", profile.traderClaimable);
  console.log("Max leverage:", profile.maxLeverage);
  console.log("Vault status:", profile.status);
}

// Fetch and decode an InvestorAccount
const account = await fetchInvestorAccount(connection, investorKey);
if (account) {
  console.log("Position count:", account.positionCount);
  console.log("Total deposited USD:", account.totalDepositedUsd);
}

// Fetch and decode a specific InvestorPosition
const [traderProfilePda] = findTraderProfile(traderKey);
const position = await fetchInvestorPosition(connection, investorKey, traderProfilePda);
if (position) {
  console.log("Shares held:", position.shares);
  console.log("Cost basis USD:", position.costBasisUsd);
  console.log("Pending withdraw shares:", position.pendingWithdrawShares);
  console.log("Withdraw ready at:", position.withdrawReadyTs);
}
```

<Tip>
  All `find*` helpers return a tuple of `[PublicKey, bump]` — the same pattern as `PublicKey.findProgramAddressSync`. The program ID is baked into the SDK — do not pass it as an argument. Cache the derived address; re-deriving on every render is unnecessary but harmless.
</Tip>
