The Arcadia REST API exposes the full proof-of-performance data layer that powers the Arcadia protocol. You can query on-chain trader scores and classification history, stream vault NAV and trade data, read investor portfolio positions, and authenticate users via Sign-In With Solana — all over HTTPS with consistent JSON responses. Public read endpoints need no credentials, while user-specific and write endpoints require a Bearer JWT. A dedicated API key path is available for lightweight, machine-to-machine score lookups.

## Base URL

All endpoints share a single versioned base URL:

```
https://api.arcadia.trade/v1
```

Every request must be made over HTTPS. HTTP requests are not supported.

## Endpoint Quick Reference

### Traders

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/v1/traders` | None | List all indexed traders |
| `GET` | `/v1/traders/:handle` | None | Get a trader's profile and current score |
| `GET` | `/v1/traders/:handle/score-history` | None | Historical score snapshots for a trader |
| `GET` | `/v1/traders/:handle/pnl-history` | None | Historical PnL data for a trader |
| `GET` | `/v1/traders/:handle/classification` | None | Trader classification and tier details |
| `POST` | `/v1/traders/init` | Bearer JWT | Initialize a new trader profile |

### Vaults

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/v1/vaults/:profile` | None | Get vault metadata and current NAV |
| `GET` | `/v1/vaults/:profile/trades` | None | Trade history for a vault |
| `GET` | `/v1/vaults/:profile/nav-history` | None | Historical NAV data points for a vault |
| `PATCH` | `/v1/vaults/:profile/deposits` | Bearer JWT (owner) | Update deposit settings for a vault |

### Investors

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/v1/investors/:wallet/account` | Bearer JWT | Investor account details |
| `GET` | `/v1/investors/:wallet/portfolio` | Bearer JWT | Current portfolio positions |
| `GET` | `/v1/investors/:wallet/flows` | Bearer JWT | Deposit and withdrawal history |
| `GET` | `/v1/investors/:wallet/notifications` | Bearer JWT | Pending notifications and alerts |

### Auth

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `POST` | `/v1/auth/challenge` | None | Request a sign-in nonce |
| `POST` | `/v1/auth/verify` | None | Verify a signed challenge and receive a JWT |
| `POST` | `/v1/auth/privy` | None | Authenticate via Privy and receive a JWT |

### Other

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/v1/me` | Bearer JWT | Fetch the authenticated user's own profile |
| `GET` | `/v1/leaderboard` | None | Global trader leaderboard |
| `GET` | `/v1/prices` | None | Current asset prices used by the protocol |
| `GET` | `/v1/score?wallet=<base58>` | `x-api-key` | Machine-to-machine score lookup by wallet |
| `POST` | `/v1/waitlist` | None | Join the Arcadia waitlist |

## Numeric Conventions

The API uses fixed-point integer representations for all financial values. When you display or compute with these fields, divide by the appropriate scale factor.

| Type | Scale | Example raw value | Interpreted value |
|------|-------|-------------------|-------------------|
| USDC amounts | ÷ 1,000,000 | `4500000` | `4.50 USDC` |
| Share quantities | ÷ 1,000,000 | `2500000` | `2.5 shares` |
| NAV multiplier | ÷ 1,000,000 | `1180000` | `1.18×` |
| Timestamps | Unix seconds | `1718000000` | Standard epoch |

All USDC values represent raw `u64` integers. There are no floating-point monetary fields in the API.

## Response Format

Every successful response returns a JSON object or array. HTTP status codes follow standard conventions: `200` for success, `201` for created resources, `400` for bad input, `401` for auth failures, and `404` when a resource does not exist.

Error responses always include an `error` string and an optional machine-readable `code`:

```json
{
  "error": "Nonce has expired",
  "code": "NONCE_EXPIRED"
}
```

## Pagination

List endpoints — including `/v1/traders`, `/v1/vaults/:profile/trades`, and `/v1/leaderboard` — support cursor-based pagination via two query parameters:

| Parameter | Type | Description |
|-----------|------|-------------|
| `limit` | integer | Maximum number of results to return per page |
| `cursor` | string | Opaque cursor token from the previous response's `next_cursor` field |

When a response includes a `next_cursor` field, pass it as `cursor` in your next request to fetch the following page. A missing or `null` `next_cursor` means you have reached the last page.

---

## Rate Limiting

Standard rate limits apply to all endpoints. If you exceed the limit, the API returns a `429 Too Many Requests` response. Build retry logic with exponential back-off into any production integration. Higher-throughput access is available — contact the Arcadia team.
