The Arcadia API supports three authentication modes, each designed for a different access pattern. Public endpoints — trader scores, vault data, leaderboards, and prices — require no credentials at all. Endpoints that read or modify user-specific data require a short-lived Bearer JWT obtained by signing a challenge message with your Solana wallet (Sign-In With Solana) or via Privy. A separate API key mechanism is available for server-side applications that need to look up trader scores without user context.

## 1. Public Endpoints (No Auth Required)

The following endpoints are open and require no `Authorization` header:

- `GET /v1/traders` and all `/v1/traders/:handle/*` sub-routes
- `GET /v1/vaults/:profile` and all `/v1/vaults/:profile/*` sub-routes
- `GET /v1/leaderboard`
- `GET /v1/prices`
- `POST /v1/auth/challenge`, `POST /v1/auth/verify`, `POST /v1/auth/privy`
- `POST /v1/waitlist`

Simply omit the `Authorization` header when calling these endpoints.

```bash
curl https://api.arcadia.trade/v1/leaderboard
```

## 2. Bearer JWT via Sign-In With Solana (SIWS)

Protected endpoints use standard Bearer token authentication. You obtain a JWT by completing a three-step Sign-In With Solana flow: request a nonce, sign a canonical message, then exchange the signed message for a token.

### Step 1 — Request a Challenge Nonce

Send a `POST` to `/v1/auth/challenge`. The body can be empty or include a `wallet` hint. The server returns a one-time nonce that expires in **5 minutes**.

<Steps>

<Step title="Request a nonce">

```bash
curl -X POST https://api.arcadia.trade/v1/auth/challenge \
  -H "Content-Type: application/json" \
  -d '{}'
```

**Response:**

```json
{
  "nonce": "a3f8c2d1e74b9056",
  "expires_at": 1718001200
}
```

<ResponseField name="nonce" type="string" required>
  The one-time nonce to embed in your sign-in message. Valid for 5 minutes.
</ResponseField>
<ResponseField name="expires_at" type="number" required>
  Unix timestamp (seconds) at which the nonce expires.
</ResponseField>

</Step>

<Step title="Construct and sign the canonical message">

Build the exact message string below, substituting your wallet's public key and the nonce you received. The newlines and formatting must match precisely.

```
Arcadia wants you to sign in with your Solana account:
{pubkey}

Nonce: {nonce}
```

For example, with a real wallet and nonce:

```
Arcadia wants you to sign in with your Solana account:
9xQeWvG816bUx9EPjHmaT23yvVM2ZWbrrpZb9PusVFin

Nonce: a3f8c2d1e74b9056
```

Sign the UTF-8 encoded message bytes with your wallet's Ed25519 private key and base58-encode the resulting 64-byte signature.

```typescript
import { sign } from "@solana/web3.js";
import bs58 from "bs58";

const message = `Arcadia wants you to sign in with your Solana account:\n${pubkey}\n\nNonce: ${nonce}`;
const messageBytes = new TextEncoder().encode(message);

// Using a Solana wallet adapter:
const signatureBytes = await wallet.signMessage(messageBytes);
const signature = bs58.encode(signatureBytes);
```

</Step>

<Step title="Verify the signature and receive a JWT">

Exchange your wallet address, base58 signature, and the original nonce for a Bearer token.

```bash
curl -X POST https://api.arcadia.trade/v1/auth/verify \
  -H "Content-Type: application/json" \
  -d '{
    "wallet": "9xQeWvG816bUx9EPjHmaT23yvVM2ZWbrrpZb9PusVFin",
    "signature": "5J9tXzQp3vR7...",
    "nonce": "a3f8c2d1e74b9056"
  }'
```

**Request body:**

<ParamField body="wallet" type="string" required>
  The base58-encoded public key of the signing wallet.
</ParamField>
<ParamField body="signature" type="string" required>
  The base58-encoded Ed25519 signature of the canonical message.
</ParamField>
<ParamField body="nonce" type="string" required>
  The nonce returned by `/v1/auth/challenge`. Must not be expired.
</ParamField>

**Response:**

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "wallet": "9xQeWvG816bUx9EPjHmaT23yvVM2ZWbrrpZb9PusVFin",
  "expires_at": 1718086800
}
```

<ResponseField name="token" type="string" required>
  The signed JWT. Include this in the `Authorization` header on all subsequent protected requests.
</ResponseField>
<ResponseField name="wallet" type="string" required>
  The authenticated wallet address, echoed back for confirmation.
</ResponseField>
<ResponseField name="expires_at" type="number" required>
  Unix timestamp (seconds) at which the token expires. Default lifetime is 24 hours.
</ResponseField>

</Step>

</Steps>

### Using the Token

Pass the JWT as a Bearer token in the `Authorization` header on every protected request:

```bash
curl https://api.arcadia.trade/v1/me \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

In TypeScript, store the token and attach it to your HTTP client:

```typescript
const response = await fetch("https://api.arcadia.trade/v1/me", {
  headers: {
    Authorization: `Bearer ${token}`,
    "Content-Type": "application/json",
  },
});

const me = await response.json();
```

### Token Expiry

Tokens are valid for **24 hours** by default. When a token expires, any protected request returns a `401 Unauthorized` response. Detect this status code and re-run the full SIWS flow to obtain a fresh token.

```typescript
async function fetchWithAuth(url: string, token: string): Promise<Response> {
  const res = await fetch(url, {
    headers: { Authorization: `Bearer ${token}` },
  });

  if (res.status === 401) {
    // Token is missing, invalid, or expired — re-authenticate
    const newToken = await signInWithSolana();
    return fetch(url, {
      headers: { Authorization: `Bearer ${newToken}` },
    });
  }

  return res;
}
```

<Tip>
  Store `expires_at` alongside the token in your session state so you can proactively refresh before the token expires, rather than waiting for a `401`.
</Tip>

## 3. Privy Authentication

If your application uses [Privy](https://privy.io) for wallet management, you can exchange a Privy token directly for an Arcadia JWT without running the SIWS challenge flow.

```bash
curl -X POST https://api.arcadia.trade/v1/auth/privy \
  -H "Content-Type: application/json" \
  -d '{
    "privy_token": "<privy_access_token>"
  }'
```

The response shape is identical to `/v1/auth/verify` — you receive a `token`, `wallet`, and `expires_at`. Use the returned JWT exactly as described above.

## 4. API Key Authentication (Machine-to-Machine)

For server-side integrations that need to look up trader scores without a user session, Arcadia provides an API key mechanism. Pass your key in the `x-api-key` header. This auth method is scoped exclusively to the `GET /v1/score` endpoint.

```bash
curl "https://api.arcadia.trade/v1/score?wallet=9xQeWvG816bUx9EPjHmaT23yvVM2ZWbrrpZb9PusVFin" \
  -H "x-api-key: your_api_key_here"
```

In TypeScript:

```typescript
const wallet = "9xQeWvG816bUx9EPjHmaT23yvVM2ZWbrrpZb9PusVFin";

const response = await fetch(
  `https://api.arcadia.trade/v1/score?wallet=${wallet}`,
  {
    headers: {
      "x-api-key": process.env.ARCADIA_API_KEY!,
    },
  }
);

const { score } = await response.json();
```

<Warning>
  Never expose your API key in client-side code or public repositories. Store it as an environment variable and make score lookup requests from your server.
</Warning>

## Error Reference

| HTTP Status | Code | Meaning |
|-------------|------|---------|
| `401 Unauthorized` | `MISSING_TOKEN` | No `Authorization` header was provided on a protected endpoint. |
| `401 Unauthorized` | `INVALID_TOKEN` | The JWT signature is invalid or the token is malformed. |
| `401 Unauthorized` | `TOKEN_EXPIRED` | The JWT has passed its `expires_at` time. Re-authenticate to get a new token. |
| `400 Bad Request` | `INVALID_SIGNATURE` | The wallet signature on the SIWS message could not be verified. |
| `400 Bad Request` | `NONCE_EXPIRED` | The nonce from `/v1/auth/challenge` was not used within 5 minutes. |
| `400 Bad Request` | `NONCE_USED` | The nonce has already been consumed by a previous verify request. |

All error responses follow the standard envelope:

```json
{
  "error": "Token has expired",
  "code": "TOKEN_EXPIRED"
}
```

<Note>
  Each nonce is single-use. If verification fails for any reason, request a fresh nonce from `/v1/auth/challenge` before retrying.
</Note>
